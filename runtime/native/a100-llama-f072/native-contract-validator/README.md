# CPU native validator — 검토 전 초안

이 디렉터리의 CMake/CPP는 아직 configure/build/run하지 않았다. Parent 검토 후 별도 CPU build만 수행한다. 기존 CUDA source/build/cache를 변경하지 않으며 `add_subdirectory`는 고정 source를 읽고 외부 build directory에만 쓴다.

계획된 호출(현재 실행하지 않음): local CMake 3.23.5로 이 디렉터리를 source, `var/runtime-build/llama-native-contract-cpu`를 build로 Release 구성하고 `--build ... --target nb-native-contract-validator --parallel 2`만 수행한다. `all`/install/UI asset target은 실행하지 않는다. GPU/backend dynamic loading/OpenMP/SSL/subprocess/llguidance/remote dependency fetch는 OFF다. Source/compiler/CMake/helper hash와 실제 CMake cache, link command, dependency 목록을 보존한다. Built binary와 static archive에 CUDA/cuBLAS/NVML 등 GPU dependency가 없는지 **실행 전에** 확인한다. `CUDA_VISIBLE_DEVICES=''`, OMP/BLAS threads=1 및 sanitized library/Python path를 유지한다.

예상 CPU build charge는 미측정이며 **3GiB cap, root free20GiB reserve, parallel2, 30분 상한**을 외부 parent runner가 강제한다. Source는 재사용한다. Cap은 명령 자체가 강제하지 않으므로 parent runner 없이 build하지 않는다. 초기 CMake configure/link 실패는 fail-closed로 보존하고 임의 dependency 설치나 source patch로 우회하지 않는다.

입력: argv1=검증된 upstream chat template, argv2=동결된 generation2 decision-branch schema, stdin=JSON bundle. `request`는 실제 새 native client의 fake-opener payload, `cases`는 7개 공개 prompt 예시+합성 거절 controls의 `{text,accept}`다. Root request schema와 template hash를 외부 runner가 검증한다. Native `oaicompat_chat_params_parse`→`common_chat_templates_apply`의 grammar와 단독 `json_schema_to_grammar(...,true)`를 둘 다 검증한다. Nonthinking에서 lazy grammar가 나오면 명시적 trigger/token replay가 필요하므로 현재 helper는 거절한다. Source converter의 incomplete warning은 직접 `fprintf(stderr)`이므로 C++가 stderr를 pipe로 받아 byte수만 센 뒤 메모리에서 버린다. 0보다 크면 FAIL이다. 이 text는 파일/결과에 보존하지 않는다. Common/native 로그는 비활성화하며 converter warning을 silent callback으로 착각하지 않는다.

출력은 status/count/byte수만이며 request/quote/token/grammar/prompt/예외본문을 출력하지 않는다. **현재 grammar corpus는 공개 예시+합성 자료만** 쓴다. 실제 forwarded sampler fields는 `server_schema::eval_llama_cmpl_schema`로 파싱하여 T/P/K/minP/penalty0/window0/seed42 및 sampler 순서까지 확인한다. CLI deepseek를 고정하므로 원래 request가 reasoning_format을 생략해도 허용하며, 원래 payload를 수정하지 않는다. 결과가 PASS여도 exact canonical parser/schema/adapter의 의미 gate는 별개다. Response envelope fakeHTTP tests는 application tests에서 별도 수행한다.

CPP는 입력을 읽기 전에 `RLIMIT_CORE=(0,0)`을 설정하며 실패하면 종료한다. Native output-format grammar에는 `generation_prompt`를 먼저 소비시켜 실제 server sampler의 prefill을 반영한다. `common_chat_parse`는 내부에서 같은 prefix를 붙이므로 JSON final content는 따로 prefix를 붙이지 않고 넘긴다. Optional vocab 경로는 실제 token의 grammar apply/accept/EOG와 문자 단위 판정을 공개 corpus에서 비교한다. `tokenizer_parity` 배열(최대32개의 공개 합성 `{text,expected_token_ids}`)이 주어지면 metadata tokenizer와 native `common_tokenize(...,false,true)`의 ID 일치도 확인하되 결과에는 개수만 남긴다. Fixture 생성기는 `../prepare_native_tokenizer_parity.py`이며 weights/Transformers/Torch를 읽거나 import하지 않는다.

Optional argv3 GGUF는 **full download SHA/header audit 이후 root 승인한 경우에만** 사용한다. 현재 제공하거나 실행하지 않는다. Vocab-only/no_alloc/n_gpu_layers0/emptydevices, context 생성 없음, tensor load 없음; pinned native source `src/llama.cpp:364`의 vocab-only early return 경로다. 동일 fd/path identity와 headerproof binding은 외부 runner가 먼저 확인한다. Built CPU-only executable은 모델 header/tokenizer를 읽을 수 있지만 weight numerical tensor를 읽거나 inference하지 않는다. Embedded/external template+prompt+grammar parity와 `context_requests`의 aggregate min/max/count만 출력한다. 요청은 실제 client payload 그대로이며 최대200, cap768/context4096을 강제한다.

현재 v2 입력/골드는 읽지 않았다. 미래 length-only 검증은 root가 별도 승인한 reviewer만 입력을 준비하고 별도 split별 numeric summary를 남긴다. 이 helper는 semantic gold 또는 model outputs를 요구하지 않는다. Hash binding, no-follow request/metadata paths, atomic report 및 CMake resource runner는 이 CPP 자체가 제공하지 않는 외부 통제다. 이 사실을 native preflight PASS 전에 숨기지 않는다.
